# Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sign in with Google or an email magic link, with users stored in our own Neon tables through Drizzle, a protected `/dashboard`, and the v1 spec's abuse protections.

**Architecture:** Better Auth runs inside the Next.js app (catch-all route at `/api/auth/[...all]`) with the Drizzle adapter on Neon Postgres. `proxy.ts` does a cookie-only redirect for app routes, and the real check is `requireUser()` on the server. With `cacheComponents` on, every session or `searchParams` read sits inside `<Suspense>`.

**Tech Stack:** Next.js 16.4.6 (App Router, `cacheComponents: true`), React 19.3, TypeScript, Tailwind 4.3, `better-auth@1.7.24` + `@better-auth/drizzle-adapter@1.7.24`, `drizzle-orm@0.45.4` + `drizzle-kit@0.31.11`, `@neondatabase/serverless@1.2.1`, `resend@6.38.1`, `@marsidev/react-turnstile@1.6.3`, `disposable-email-domains-js@2.0.0`, `vitest@5.1.0`, `@next/env` (matches `next`). Node 26.

**Spec:** [docs/superpowers/specs/2026-11-14-auth-design.md](../specs/2026-11-14-auth-design.md) (parent: [v1 design spec](../specs/2026-11-14-ai-resume-builder-v1-design.md))

## Global Constraints

- Read `node_modules/next/dist/docs/` before writing routing, proxy or server-action code. Middleware is **`proxy.ts`** in Next 16 (Node runtime, no `runtime` export).
- `cacheComponents: true`: reading `headers()`, `cookies()` or `searchParams` outside `<Suspense>` is a build error. Don't put a session read at a layout's top level.
- No secrets in client code. The only `NEXT_PUBLIC_` variable is `NEXT_PUBLIC_TURNSTILE_SITE_KEY`. Server-only modules import `"server-only"` (aliased to an empty module in Vitest).
- **Never run tests or migrations against the production branch** (`br-long-heart-baglwvz7`, project `lively-dust-59634864`). If a `dev`/`test` branch can't be created, stop and ask the owner.
- Magic links: **15 minutes** (`expiresIn: 900`), single use.
- Rate limit: magic-link endpoint **5 requests per IP per 600 s**; global default 100 per 10 s; storage `"database"`; enabled everywhere except `NODE_ENV === "development"`.
- Client IP header from `AUTH_IP_HEADER`, default `x-forwarded-for`.
- Production must never log a magic link instead of emailing it. A missing `RESEND_API_KEY` or `EMAIL_FROM` in production is an error.
- Return-to paths: same-site relative only. Fallback `/dashboard`.
- Product name comes from `siteConfig.name` in `lib/site-config.ts` (placeholder `"AI Resume Builder"`).
- Google sign-in on `http://localhost:3000` and `https://ai-resume-builder-navy-seven.vercel.app` only, not previews.
- Commit on `feat/auth` after each task. Don't push or merge without the owner's say-so.

## Review Focus

1. **Stale or forged session cookie:** the proxy sees a cookie, but the server finds no session. Expected: one redirect to `/sign-in`, with no loop between `/sign-in` and `/dashboard`. → Task 4 test `requireUser redirects on an unknown session token`; Task 5 makes `/sign-in` redirect only on a *real* session.
2. **Email casing and whitespace** (`" Ana@Example.com "`): expected to be the same user as `ana@example.com`, and the disposable check matches subdomains (`x.mailinator.com`). → Task 2 test `normalizes email so casing does not create a second user`; Task 3 test `rejects disposable subdomains`.
3. **Return-to tricks** (`//evil.com`, `/\evil.com`, `https://evil.com`, `%2F%2Fevil.com`, `javascript:alert(1)`): expected to fall back to `/dashboard`. → Task 4 `safeReturnTo` table test.
4. **Magic link opened twice, or after expiry:** expected to land on `/sign-in?error=…` with a readable message, not a crash or a blank page. → Task 2 tests `magic link works once` and `magic link expires after 15 minutes` (assert redirect location contains `error=`); Task 5 maps the error codes to copy.
5. **Email provider failure:** Resend returns an error. Expected: the request fails, and the form shows "Couldn't send the email" instead of "Check your email". → Task 2 test `send failure surfaces as an error`; Task 5 form handles `error`.
